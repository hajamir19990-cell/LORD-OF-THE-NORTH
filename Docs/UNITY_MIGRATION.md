# Unity migration plan and implementation notes

## Why this branch exists
The Unreal branch contains C++ gameplay source and fifteen OBJ interchange meshes, but its nine .umap scenes had not yet been generated by Unreal Editor. The Unity migration therefore starts from the portable source meshes and reimplements runtime gameplay in C#, rather than pretending Unreal binary scenes can be converted directly.

## Implemented in this migration branch
- Unity 6.3 LTS project and URP package manifest.
- Fifteen OBJ source meshes copied into UnityProject/Assets/Art/SourceOBJ.
- Editor scene generator for nine landscape scenes with rolling terrain, imported architecture, pine groves, props, player start, NPC, quest object, lighting and fog.
- Android build pipeline configures landscape orientation, ARM64 and IL2CPP.
- C# player controller, camera follow, touch input, stats HUD, stackable inventory, cloak/trinket equipment, quest interactions, region map and persistent player/quest state.
- Editor-generated mobile URP pipeline/renderer assets and procedural snow terrain layer.
- OBJ import settings convert centimeter-scale, Z-up source meshes into Unity meter/Y-up space and generate secondary lightmap UVs.
- Terrain-sampled placement and simple blocking colliders for major structures, road segments and settlement boundaries.
- Per-region player-position checkpoints in addition to persistent stats, quest progress and inventory.
- Static repository and OBJ geometry validator.
- Manual Android cloud-build workflow using GameCI.

## Current prototype limitations
- The player is still a temporary capsule greybox; no final skeletal character, rig or animation pack has been integrated.
- The Editor scene generator creates first-pass greybox layouts from existing OBJ meshes; it does not make final art production-ready.
- The nine regional layouts currently share a common composition with region-specific terrain noise. Each needs its own architectural silhouette, set dressing, landmarks, traversal and visual review.
- The prototype uses simple OnGUI overlays and direct touch zones; final polished mobile UI remains to be built.
- There is no combat, enemy AI, branching dialogue, crafting, audio, cinematic system, multiplayer or full save-slot UI yet.
- Terrain textures, snow PBR materials, LODs, occlusion, baked lighting and mobile performance tuning remain production tasks.
- Scene generation and C# compilation require a real Unity Editor run. Static validation alone does not verify them.

## Acceptance gates
1. Unity 6.3 LTS opens the project and imports every OBJ without errors.
2. Editor bootstrap creates and saves all nine .unity scenes.
3. Unity compiles all runtime and Editor C# scripts without errors.
4. EditMode/PlayMode tests pass.
5. Android IL2CPP ARM64 build produces an APK.
6. APK installs and launches on a real Android device in landscape.
7. Touch movement, camera, quest flow, save/restore and region unlock/travel pass device QA.
8. Each region is profiled for memory, frame pacing, draw calls and load times before release.
